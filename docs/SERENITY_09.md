# Serenity 0.9 — delivered scope and limits

Serenity 0.9 is a developer preview containing a native read-only observer,
deterministic memory-pressure classification, a guarded authority state machine,
a bounded event log, localhost HTTP API, static WebUI, module packaging scripts,
and host CI.

## Milestones delivered in source
1. Normalized memory and PSI parsing.
2. Live procfs memory observation.
3. Bounded process enumeration and optional process metadata.
4. Deterministic memory-pressure policy classification.
5. Fail Safe Gate health contract and heartbeat timeout.
6. Bounded, thread-safe event history.
7. Supervisor sampling loop and JSON status endpoints.
8. Loopback-only dashboard for status, RAM, processes, and events.
9. ARM64 Magisk-style module staging and NDK packaging script.
10. Host build, test, and GitHub Actions workflow.

## Authority and safety
The supervisor starts in LMKD_FALLBACK. No code in this preview disables, patches,
or replaces LMKD behavior. The Fail Safe Gate unit can grant AETHER authority only
when all health predicates are true, and it returns to fallback on heartbeat
expiry. The current supervisor has no in-process Runtime Agent and never attempts
activation, so it remains in fallback.

The policy core classifies observations and emits decision labels. This preview
does not execute reclaim, process-kill, kernel tuning, or LMKD control operations.
The dashboard is local-only and read-only.

## Not yet device-ready
- ShadowHook and Dobby are evaluated candidates, not linked or installed.
- No LMKD hook target, symbol, offset, or ABI has been validated.
- The Runtime Agent and its in-process heartbeat producer are not implemented.
- The gate is not connected to a real LMKD policy suppression/restoration mechanism;
  it is a tested state-machine contract only.
- No Android device, SELinux, or root-manager install validation has been completed.
- The module archive is generated by the build script and must be tested on a
  disposable test device before normal use.

Serenity 0.9 is source-complete for the observation/supervisor developer preview,
not a complete LMKD takeover release. A true AETHER policy-authority release
requires audited LMKD integration and tested rollback on target devices.
